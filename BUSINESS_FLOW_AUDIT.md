# Invoice Generator business flow comparison

Compared on 2026-09-29 against `samarth-vamshy/invoice_generator`, commit
`dc8d38f8bddf164ccc3753408e9fffe8266c4de6`. GitHub `main` and `HEAD` both pointed to
this commit when checked. Target: `Invoice_generator_Azure`.

## Source comparison

The following modules match the committed source by Python syntax tree, allowing
only the import rename from `config` to `invoice_settings`:

- `domain.py`, `errors.py`, `invoice_engine.py`, `invoice_service.py`
- `local_invoice_service.py`, `pdf_renderer.py`, `routing.py`
- `sharepoint_service.py`, `ai_client.py`

The business `Settings` class retains the source's limits and credentials. A later
user-requested change removed the shared Generated By fallback; SharePoint now
uses the current person's site identity or an explicit per-user mapping. Card content and
fields match; card actions use the target Teams SDK's `Action.Execute` transport.
The original `agent.py` routes are implemented by `invoice_routes.py`, registered
on the target project's existing `App` in `app.py`. The existing Teams SDK LLM
handler supplies general conversation with invoice-specific instructions.

## Corrections from this audit

1. `src/invoice_routes.py`: restored the source's sender email and channel-data
   email fallback for the SharePoint Generated By identity. The Teams SDK models
   channel data as an object, so it is normalized before reading these fields.
   Restored safe review-value and redacted message-preview diagnostics.
2. `src/cards.py`: Review and random Generate collect form inputs; navigation
   actions use `associatedInputs: none` so incomplete required fields do not
   prevent Cancel or Home. See the [Action.Execute schema](https://learn.microsoft.com/en-us/adaptive-cards/schema-explorer/action-execute).
3. `tests/test_business_flow_parity.py`: added ten tests covering the complete
   custom and partial random workflows, Person identity sources, navigation,
   natural-language prefilling, conversation start, legacy submit routes,
   confirmation isolation/expiry, required names and diagnostics.

## Verification and limits

All 36 tests pass. Tests use real Teams SDK activity/card models, domain
validation, invoice generation and PDF rendering, with fake conversation delivery
and an in-memory Graph boundary. The shared Person fallback is intentionally
removed from the checked source behavior.

This audit does not prove live Teams delivery or live SharePoint uploads. The
previous live Graph check returned HTTP 401 and a token with no application
roles; permission configuration still needs a successful live check. No tenant
permissions, bot registration, launch configuration, endpoint, manifests, Toolkit
YAML, credentials, or Azure templates were changed in this audit.

The target's existing Teams app and `/api/messages` entry point are retained.
The source repository's Playground runtime and packaging were not imported.
