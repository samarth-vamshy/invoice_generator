# Invoice Generator

This is the existing Microsoft 365 Custom Engine Agent using the Microsoft 365 Agents SDK and aiohttp. Its endpoint remains `http://localhost:3978/api/messages` by default.

## Agent flow

Home → Generate Invoices → Generate Random or Customize. Random accepts a count and purpose and may vary company names. Customize requires seller and buyer names; any entered addresses and tax IDs are used exactly, and the selected tax type and rate apply to every invoice. Single creates one PDF. Batch creates the requested number of PDFs with the same company details, tax settings, chosen invoice date, and line item descriptions; invoice numbers and amounts vary. The Review card shows all entered company fields and tax settings before Generate. Both paths use `InvoiceRequest`, the same Decimal calculation and validation engine, the same ReportLab renderer, and the same SharePoint upload and metadata pipeline. A generated invoice counts as stored only after its PDF and all required metadata are verified in the Invoice Library. A failed metadata update triggers deletion of that uploaded PDF; any cleanup failure is logged and the item is reported as failed.

Search Invoices queries SharePoint library metadata, not local files or conversation state. Search by purpose, invoice number, batch ID, or generated date. Result cards link to SharePoint items.

## SharePoint setup

Keep the existing `SHAREPOINT_SITE_ID` and `SHAREPOINT_LIBRARY_ID`; the agent reads them from the central settings layer. `SHAREPOINT_LIBRARY_ID` may be either the document library's Graph list ID or its `b!` drive ID. For a drive ID, the service resolves the related list ID once and verifies that the list points back to the same drive. The library must have these display names: Invoice Number, Generated Date, Purpose, Invoice Type, Batch ID, Generated By, Seller Name, Buyer Name, Total Amount, and Tax Type. **Generated By must be a single-value Person column.** The service reads each column's actual internal name once and uses that name for updates.

To enable live Graph access, configure `SHAREPOINT_GRAPH_TENANT_ID`, `SHAREPOINT_GRAPH_CLIENT_ID`, and `SHAREPOINT_GRAPH_CLIENT_SECRET` for an Entra application with the Microsoft Graph **Sites.Selected** application permission and a **write** grant to this specific site. The service can reuse populated `CONNECTIONS__SERVICE_CONNECTION__SETTINGS__TENANTID`, `CLIENTID`, and `CLIENTSECRET` values when the separate SharePoint values are absent. Use the client secret **Value** from Entra App registrations > Certificates & secrets, never the Secret ID. The Value is shown only when the secret is created. An administrator must configure the app permission and site grant; the bot does not change permissions.

For the Person column, the agent uses the current user's AAD ID or email when it can find a matching SharePoint site user. `SHAREPOINT_USER_LOOKUP_IDS` can map known AAD IDs or emails to valid SharePoint User Information List IDs, for example `{"user-guid": 17}`. If the user cannot be resolved, `SHAREPOINT_GENERATED_BY_LOOKUP_ID` can identify a **real** site user for local development. There is no fabricated default. If identity cannot be resolved and no valid fallback is configured, generation stops before PDF rendering or upload.

Microsoft's [Selected permissions overview](https://learn.microsoft.com/en-us/graph/permissions-selected-overview) explains the site-specific grant. The agent does not create this grant.

## Configuration

Copy variable names from `.env.example`. `INVOICE_MAX_BATCH_SIZE` defaults to 50. Random generation defaults to purpose Testing, currency INR, amount range 1,000–10,000, and 30 uniqueness attempts per invoice. These can be changed with `DEFAULT_PURPOSE`, `DEFAULT_CURRENCY`, `RANDOM_MIN_AMOUNT`, `RANDOM_MAX_AMOUNT`, and `RANDOM_GENERATION_MAX_RETRIES`. `SHAREPOINT_SEARCH_MAX_ITEMS` bounds a metadata scan; a query that hits the bound reports that it must be refined.

Install `src/requirements.txt` and run `python src/app.py` from the project root, or use the existing Agents Playground debug configuration. The previous `local_invoice_service.py` remains for local core tests; the active agent uses `invoice_service.py` and `sharepoint_service.py`.

## Verification

Run `python -m unittest discover -s tests -v`. Tests cover the active card routes, random batches of 3/5/10 unique invoices, custom batches, SharePoint metadata, search, missing identity, and partial metadata failure using an in-memory Graph boundary. A live check also requires valid Graph credentials, the site grant, the column schema, and a Person mapping. After changing `.env`, restart the Python agent so the existing `/api/messages` process reads the new values.
